## 실제 실행 시도

Windows의 앱 번들 Codex CLI `0.171.0-alpha.13`에서 새 임시 프로젝트로 가상
예제를 실행했습니다. 첫 시도는 프로젝트 미신뢰로 로컬 설정이 비활성화됐습니다.
검토한 새 프로젝트에 표준 신뢰를 적용한 후에는 다음 호스트 오류로 셸과 Node의
파일 접근이 모두 차단됐습니다.

```text
app runtime provisioning service is unavailable; refusing helper fallback
```

이는 이 패키지의 서버 인증 오류가 아닙니다. 패키지는 서버를 띄우지 않습니다.
다만 오류의 원인이 별도 호스트에 있다는 사실이 패키지의 실제 팀 작동을 증명하지는
않습니다. 실행 결과의 모델 서술만으로 정확한 역할 등록·호출을 검증 완료 처리하지
않았고, 보고서 생성·채택·독립 검토·읽기 확인도 완료되지 않았습니다.
권한·샌드박스를 해제하는 우회는 적용하지 않았습니다.

## 정식 배포로 올리는 조건

Windows와 Mac의 Codex **앱**에서 각각 새 프로젝트를 열고 START-HERE의 가상 예제로
실제 역할 선택, 보고서 저장, 메인의 채택, 독립 판단 검토, 최종 파일 읽기까지
관찰 기록을 남깁니다. 최소 점검에서 실행하지 않은 나머지 역할도 각 방법에 맞는
가상 사례로 호출해 확인합니다. 그 전에는 안정 버전이나 모든 학생 환경에서 작동을
보장하는 것으로 표시하지 않습니다.

가상 예제는 투자 성과나 실제 데이터 접근의 검증이 아닙니다. 원본 서비스의
보안 테스트 결과는 이 배포본의 파일 기록을 인증된 원장으로 만들지 않습니다.
