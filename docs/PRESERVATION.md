## 실패 원인과 설계 선택

현재 Codex 공식 문서는 사용자 정의 서브에이전트가 부모의 권한·provider·MCP를
상속하며, 역할 파일의 `mcp_servers`가 이를 덮어쓰지 않는다고 설명합니다.
원본 역할 파일은 같은 MCP 이름에 역할별 `TRADINGCODEX_MCP_PRINCIPAL`과 도구 목록을
넣습니다. 따라서 최신 호스트에서 그 파일이 존재한다는 사실만으로 역할별 서비스
인증과 도구 노출이 성립한다고 볼 수 없습니다.

이 패키지는 그 인증을 이름 변경이나 모든 도구 허용으로 우회하지 않습니다.
원본 프로젝트와 분리된 연구 전용 프로젝트에서 서비스 자체를 요구하지 않는
저장 경로를 사용합니다. 원본의 주문 경계가 필요한 사용자는 별도 실행 시스템의
실제 인증·승인·권한·감사 경로를 검증해야 합니다.

[기준 원본](https://github.com/moneybuilderjay-cmyk/Hyperpass-Tradingagent/tree/a15871c922870f9803f819d9b994888ec81eabc1).

## 추적 방법

`provenance/upstream-manifest.json`은 원본 경로, 고정 커밋 링크, 원본 SHA-256,
이식한 방법 파일의 SHA-256을 기록합니다. `provenance/upstream/*.txt`는 원본
지침의 보존 사본이며 실행 지침이나 설치 대상이 아닙니다. 공식 원본 소스가 우선합니다.

`tools/import_upstream.py`는 유지보수용 이식 절차입니다. 패키지를 만들 때만 실행하며
학생 PC에서 서버·패키지·인증을 설정하지 않습니다. 팀 계약을 바꾸는 변경은
이 표, 실제 역할 호출 검증, 배포 버전을 함께 갱신해야 합니다.
