# Hyperpass research team

Use the root `AGENTS.md` contract. Native Codex owns tool discovery, reasoning,
child lifecycle, permissions, and scheduling. No local daemon or MCP is needed.

## Readiness

For first use follow `START-HERE.md`, not a live financial task. Check actual
native role availability; a directory listing is only a structural check.
For ordinary follow-ups reuse recorded readiness and check only affected gaps.
Never install dependencies or reconfigure an existing MCP to answer research.

## Coordinate

1. Preserve the outcome, universe/instrument, horizon, as-of and exclusions.
   A narrow fact/status answer needs no run or child. For material research read
   `references/research-framing.md` and identify the causal unknowns that matter.
2. For a substantive workflow create a unique run record as specified by
   `references/records.md`. Freeze the mandate and explicitly selected context
   versions. If an explicitly selected Brain/Strategy cannot be resolved, wait
   for it instead of inventing a substitute. Read `references/context.md` only
   for overlays, memory, wiki, strategy or investor-context work.
3. Choose the smallest useful exact profiles. See `references/roles.md`. Use the
   native tool's actual schema to select the exact role; do not invent a tool
   parameter or relabel a generic agent as an authenticated profile. Pass a
   compact brief with question, mandate, run path, data-family owner, input IDs,
   output path, readiness target and no-order boundary. Start with a fresh child
   context where supported; do not copy unrelated chat history.
4. Parallelize independent questions within available concurrency. Assign each
   data family one owner; supplied evidence is reused by ID/path/version. One
   unavailable evidence-producing profile may use a generic child with its
   complete bounded role brief, explicitly labeled as fallback. Required Risk
   Manager or Judgment Reviewer work cannot use that fallback.
5. Reuse an existing child's session for work it still owns. Wait only for a
   real live target returned by the runtime. Record actual child identity and
   returned artifacts; never invent parallelism, completion or peer approval.
6. Review returned evidence against the brief, source posture, causal map,
   numeric quality and declared inputs. Verify files by reading them. Record
   `accepted`, `revise`, `blocked`, or `waiting`; only accepted current-run
   versions support synthesis. A file or hash alone proves neither author nor
   factual correctness. Mark native child attribution separately.
7. After each accepted result, apply the feedback loop below. Independent
   portfolio/risk judgment or adversarial review is used when it can change a
   consequential decision; do not force every role on every question.
8. Synthesize the evidence-to-conclusion chain under the same mandate. Keep
   competing explanations, strongest contrary evidence, uncertainty, material
   gaps, invalidation, update triggers and confidence visible. Distinguish
   evidence readiness from action readiness; action remains `research-only`.
9. Save one synthesis identity per run when it has decision/handoff/reuse value,
   with numbered corrections rather than replacement. A decision-grade accepted
   synthesis gets an evidence-only judgment snapshot for later evaluation; it
   does not mean user adoption or trade approval. Link the actual absolute report
   path and give a self-contained answer. Do not save duplicate trivial reports.

## Feedback loop

- Same owner: follow up with the exact target artifact/version, separate IDs of
  triggering evidence, and the missing delta. If the target ID is missing, wait.
- New specialty: delegate the causal gap with consumed IDs and an explicit new
  artifact instruction. Do not have the current owner impersonate that specialty.
- Material conflict: obtain independent `judgment-reviewer` or `risk-manager`
  review. A reviewer can maintain, change, qualify or abstain; no forced neutrality.
- Continue only while an obtainable answer could materially change the result.
  Preserve an unresolved gap and lower readiness instead of looping or guessing.

## Evidence and methods

For external facts use `references/sources.md`; for conclusion-driving numeric
work use `references/calculations.md` and `references/data-qc.md`. Use
`references/scenarios.md`, `references/forecast.md`, or
`references/anti-overfit.md` when those outputs are requested or material.
Do not require a fixed source count or treat all secondary sources as unusable.
Data access and source quality are separate. No capability implies permission.

## Unavailable capabilities

No web/data access: use supplied evidence with its limitations; missing current
data blocks dependent current claims. No calculator/runtime: report the numeric
gap and do not invent outputs. No file writes: return research but identify
durable memory as unavailable. No exact independent review: block the dependent
decision. Do not downgrade these failures into a silent claim of full success.
